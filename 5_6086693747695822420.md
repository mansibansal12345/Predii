# Vehicle Specification Extraction System

A complete RAG (Retrieval-Augmented Generation) pipeline for extracting structured vehicle specifications from PDF service manuals using Mistral AI.

** Optimized for Ford, GM, and similar service manual formats with symptom charts and procedure tables.**

---

##  What This Does

Extracts structured specifications from automotive service manuals, including:
- **Torque values** from TIGHTEN instructions
- **Tire pressures** from specification tables
- **Fluid capacities** from maintenance procedures
- **Clearances and gaps** from inspection procedures
- **Component specifications** from symptom charts

**Input**: PDF service manual (Ford F-150, GM, Toyota, etc.)  
**Output**: Structured JSON/CSV with component specifications

```json
{
  "component": "Wheel Nut",
  "spec_type": "Torque",
  "value": "110",
  "unit": "Nm",
  "context": "TIGHTEN to specification - Section 204-04"
}
```

### Optimized for Service Manual Format

Based on your Ford F-150 sample, the system includes:

1. **Table Detection**: Recognizes symptom charts and specification tables
2. **Larger Chunks**: 600 characters (vs 500) to keep complete procedures together
3. **Enhanced Cleaning**: Removes page footers, file paths, dates
4. **Action Word Extraction**: Extracts torque from "TIGHTEN to X Nm" instructions
5. **Section Awareness**: Preserves references like "REFER to Section 204-04"

### Sample Manual Format Handled

```
Symptom Chart — Suspension System
Condition          Possible Sources    Action
------------------------------------------------------
Sway or roll       Loose wheel nut(s)  TIGHTEN the wheel nut(s) to
                                       specification. REFER to Section 204-04.
```

The system extracts: **Wheel Nut → Torque → [value] → [unit]**

##  How It Works

### 1. PDF Text Extraction
- Uses PyMuPDF to extract text page-by-page
- Cleans and normalizes the text
- Preserves page numbers for context

### 2. Semantic Chunking
- Splits text into ~500 character chunks
- Tries to keep related content together
- 100 character overlap prevents splitting specs

### 3. Embedding Creation
- Converts text chunks to 384-dim vectors
- Uses Sentence-Transformers model
- Captures semantic meaning, not just keywords

### 4. Vector Indexing
- Builds FAISS index for fast search
- Enables similarity-based retrieval
- Finds relevant chunks in milliseconds

### 5. Query Processing
- Your query is converted to a vector
- FAISS finds 5 most similar chunks
- Retrieved text provides context to LLM

### 6. LLM Extraction
- Mistral AI reads retrieved chunks
- Extracts structured specifications
- Returns JSON with component, type, value, unit

##  Design Decisions

### Why These Tools?

**PyMuPDF over pdfminer/pypdf**
- Faster text extraction
- Better handling of complex layouts
- Active development

**Sentence-Transformers over OpenAI Embeddings**
- Free (no API costs)
- Fast local inference
- Good quality for technical text
- 384 dimensions (efficient)

**FAISS over Chroma/Pinecone**
- Extremely fast search
- No external dependencies
- Perfect for moderate document sizes
- Simple integration

**Mistral over OpenAI**
- Competitive pricing
- Strong multilingual support
- European data residency
- Open-source options available

##  Limitations

### Current Limitations
1. **Text-only**: Doesn't process images/diagrams
2. **English-optimized**: Works best with English manuals
3. **Tables**: Limited support for complex table structures
4. **Scanned PDFs**: Requires text-based PDFs (not scanned images)

### Potential Improvements
1. Add OCR for scanned PDFs
2. Implement table extraction
3. Support multi-language manuals
4. Fine-tune for automotive domain
5. Add caching for repeated queries
6. Build knowledge graph of relationships
